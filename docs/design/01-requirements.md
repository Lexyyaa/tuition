# 요구사항 구체화

> 아래 두 문서를 구현 가능한 단위로 쪼갠다.
> - 과제 원문: [00-assignment.md](00-assignment.md)
> - 분석: [00-analysis.md](00-analysis.md)
>
> 이 문서가 **요구사항 ID와 테스트 케이스 ID의 유일한 출처**다.

## ID 규칙

| 접두 | 뜻 | 형식 | 예 |
|---|---|---|---|
| `FR` | 기능 요구사항 | `FR-{F}.{항}` | `FR-2.1` |
| `NFR` | 비기능 요구사항 (동시성·정합성·기술 조건) | `NFR-{항}` | `NFR-3` |
| `SUB` | 제출물 요구사항 | `SUB-{항}` | `SUB-2` |
| `D` | 모호한 점에 대한 결정 | `D-{항}` | `D-4` |
| `TC` | 테스트 케이스 | `TC-{F}-{번호}` | `TC-2-07` |

- ID는 재사용하지 않는다. 삭제하면 번호를 비워 둔다
- `{F}`는 `task_list`의 기능(F) 번호와 같다
  - F1 기초 설정은 `FR`이 없고 `TC-1-xx`만 있다 (값 객체 · 공통 검증)
  - 첫 도메인 기능은 F2 → `FR-2.x` · `TC-2-xx`
- 원문 한 문장 = 요구사항 한 행
  - 한 문장에 규칙이 둘이면 행을 나눈다
- 원문에 없는데 필요해서 추가한 요구사항
  - `원문` 열에 `(파생 H-n)`이라 적는다
  - 필요하면 `D`로 근거를 남긴다
- 분석 문서의 ID를 출처로 쓴다
  - `S-n` 원문 문장
  - `H-n` 숨은 요구사항
  - `C-n` 결정 항목 → 사용자가 정하면 §5 `D-n`
- `D-n`의 번호는 분석 `C-n`의 번호와 1:1로 같다 (D-1 = C-1의 결정)

## 1. 과제 범위

**필수**
- F2. 학원 식별 · 강좌 · 수강 (정원 동시성, 기간 중복 방지)
- F3. 원비 산정 · 고지서 생성 (일할 계산, 형제 할인, 금액 수정, 자동 스케줄)
- F4. 발송 (2대 중복 없는 점유, 합산 초당 100건, 금지 시간대, 가짜 클라이언트)
- F5. 발송 결과 (웹훅 확정, 15분 미확정, SMS 대체)
- F6. 납부 (멱등성, 부분 납부, 미납 목록)
- F7. 운영 (진행 현황, 실패 조회, 이력, 재발송)
- F8. 미납 안내 (기한 경과 3일 · 7일)

**선택**
- 학원별 발송 시각 설정 (S-69) — **구현하지 않는다** (D-35)
  - README에 설계 방향만 기재한다

**범위 밖** (구현하지 않는다 — 면접에서 물어보면 여기가 근거)
- 인증·인가 (S-12. 식별은 헤더로 시뮬레이션)
- 학원별 발송 시각 설정 (S-69, D-35) — 선택 요구, 필수에 시간 집중
- 부속 API 중 검증에 불필요한 것 (D-48. seed로만 준비)
  - 강좌 수정·삭제
  - 수강생 분리 등록 API (수강 등록에 수강생 정보 포함)
  - 납부 취소·환불
  - 학원 플랜 설정 API (플랜은 seed 값)
  - 형제 할인율 설정 API (할인 설정은 seed 값, D-5)
- 공휴일·휴강 반영 (S-34 심문에서 확인 — 원문에 근거 없음, 수업 요일만 사용)
- 과거 기준일의 미납 목록 정확성 (D-29. 현재 상태 기준으로 판정, 한계는 README 기재)

> 모든 `H-n`(H-1~H-41)은 `FR`·`NFR`로 반영했다. 범위 밖으로 둔 H는 없다 (§6 대응표 참조)

## 5. 모호한 점과 결정

> 분석 §7의 결정 55건 전부. `D-n` = `C-n` (번호 1:1).
> `결정` · `근거`는 §7 기록 그대로다.

### D-1. 고지서의 단위

- 관련: C-1 · FR-3.8 · FR-3.5 · FR-6.1
- 원문: S-3 "…매달 학부모에게 원비 고지서를 알림톡으로 발송…"
- 선택지
  - A: 수강 등록 1건 = 1장 — 대응 단순 / 학부모가 여러 장 수신
  - B: 학부모 1명 · 1개월 = 1장, 항목 합산 — 알림 1건 · 형제 할인 자연 / 항목 수정 · 납부 배분 · 학부모 모델 필수
  - C: 수강생 1명 · 1개월 = 1장 — 학부모 모델 없이 합산 / 형제 할인엔 여전히 학부모 필요
- **결정**: B 학부모 1명·1개월 = 고지서 1장, 항목 합산
- **근거**: 사용자
- 남는 한계: 항목별 금액 수정 · 부분 납부 배분 규칙이 필요해 범위가 커진다 (납부는 고지서 총액 기준으로 단순화)

### D-2. "해당 월 유효 수강 등록"의 경계

- 관련: C-2 · FR-3.7
- 원문: S-41 "월을 지정해 해당 월 유효 수강 등록 전체에 고지서를 생성"
- 선택지
  - A: 시작일 ≤ 월 말일 그리고 (종료일 없음 또는 종료일 ≥ 월 1일) — 일할 산정과 일치 / 하루치 고지서 발생
